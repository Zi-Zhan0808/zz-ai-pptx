# 按给定模板创作

用户把一份 `.pptx` 递过来说"照这个做"时，最容易犯的错是**照着看**而不是**打开读**。
看出来的版本是"差不多是这个绿、差不多是这个条"，打开读能拿到同一样东西本身。

## 为什么"克隆"比"模仿"可靠

一个 `.pptx` 里，让模板看起来像它自己的东西分三层，各自都只能靠读文件拿到：

| 层 | 里面是什么 | 拿到它的方式 | 拿不到的后果 |
|---|---|---|---|
| theme | 命名颜色槽、字体 | 解析 theme XML | 颜色靠眼睛估，整册偏一点 |
| layout | 标题条、序号圆徽、页脚带 | 新页用**它的**版式 | 装饰重画一遍，尺寸差 1–2pt，一眼假 |
| slide | 成品排版（封面、目录、封底） | 整页克隆 + 换字 | 用矩形拼个"像"的封面，处处差一点 |

第三条最常被低估。封面不是一个版式，是一次**构图**：一块满版色、一条细线、
三档字重的文字按固定偏移摞起来。用基本图形重新拼出来，结果永远是"差一点"，
而"差一点"在观感上等于"坏的"。克隆出来的封面所有形状都还是真形状，
图片关系也重映射过，所以既可编辑、又像素级一致。

## 流程

```bash
# 1. 读
python scripts/template_ingest.py 模板.pptx --out work/template

# 2. 删机构标识（先给用户看清单，确认后再删）
python scripts/template_ingest.py 模板.pptx --out work/template --strip-all-candidates

# 可选：顺手删掉模板自带的使用说明页
python scripts/template_ingest.py 模板.pptx --out work/template \
    --strip-all-candidates --drop-pages 1
```

删页之后会**重新解析一遍清理后的文件**再写 profile。必须如此：删掉第 1 页会让
后面每一页的页码前移一位，沿用原编号的 `pages.cover.index` 会静默指向另一页。

第 1 步产出：

- `work/template/template_profile.json` — 机器读的画像，**可以手改**
- `work/template/template_profile.md` — 给你读的，含版式表、页面表、标识评分表
- `work/template/模板-clean.pptx` — 第 2 步才有

## 机构标识是怎么找出来的

校徽没有名字可找（形状叫 `图片 19`），只认证据。每个图片按下列规则打分：

| 证据 | 分 |
|---|---|
| 被某个版式或母版使用（设计家具，不是内容） | +3 |
| 出现在 ≥2 页 | +2 |
| 出现在 ≥4 页 | +3（替代上面那条） |
| 完全落在顶部标题带内 | +2 |
| 宽高比 ≥ 2.5（字标是横条，插图不是） | +2 |
| 大尺寸且接近 4:3 / 16:9（几乎肯定是插图） | −4 |
| 与已识别的标识像素尺寸完全相同（同一素材的另一裁切） | +2 |

≥4 分算候选。**必须请用户确认再删**——一张合法的对照图用了两次也会得分，
静默删掉用户的图比留下别人的校徽更糟。

删的时候是删元素 + 断关系，不是隐藏：隐藏的图片照样在文件里，用户一开图层就回来了。
断开关系后 python-pptx 保存时就不再打包该图片部件，文件会真的变小。

## profile 怎么读

```jsonc
{
  "canvas": {"w": 13.333, "h": 7.5},
  "theme": {"colors": {"accent1": "006334", ...}, "fonts": {...}},
  "layouts": [
    {"index": 0, "name": "2_标题幻灯片", "slide_count": 18,
     "title_box": [1.325, 0.383, 10.58, 0.725],   // 标题占位符位置
     "content_top": 1.31,                          // 内容从这个 y 往下才安全
     "chrome": [...]}                              // 版式自己画的装饰
  ],
  "slides": [...],            // 页面清单：哪页有什么，用来挑克隆对象
  "pages": {                  // 三个签名页 + 槽位提案
    "cover":   {"index": 5, "slots": {...}, "widen": {}, "review": [...]},
    "agenda":  {"index": 8, "slots": {...}},
    "closing": {"index": 30, "slots": {...}, "widen": {}}
  },
  "brand_marks": [...]         // 每张图的得分与证据
}
```

`content_top` 是从版式装饰的实际下沿算出来的，用它而不是猜"大概留 1 英寸"，
内容就不会压到标题条上。

`pages.*.review` 是给人看的三列表：槽位名、形状名、**原本写的是**。
自动提案会错，所以要带原文对照——三行扫一眼就知道哪条要改。

## 槽位映射

`slots` 把语义名映射到形状名：

```json
"cover": {"index": 5, "slots": {
  "kicker": "文本框 1", "title_en": "文本框 9", "title_cn": "文本框 7",
  "dept": "文本框 4", "group": "文本框 14",
  "presenter": "文本框 10", "date": "文本框 11"}}
```

形状名是本地化的、每个文件都不同，所以不猜、只读。
自动规则按文字内容判断（`汇报人` → presenter，`课题组` → group，
最长中文 → title_cn，最长西文 → title_en），并对不同角色区别对待：

- **目录页只有标题和列表**，所以只映射 `heading`。把某一条目录项认成"标题"
  是最容易犯的错。
- **封底页只有一句大话**，所以取字号最大的一段映射到 `text`。
  按字数取会输给上面那行英文小字。

## 窄框要加宽

设计师的文本框是紧贴他自己那句话画的。换成更长的课题组名，行会在词中间断，
这是"借来的页面开始显坏"的典型信号。profile 里声明：

```json
"cover": {"index": 5, "widen": {"文本框 14": 2.6, "文本框 11": 4.6}}
```

只在该框右侧确实空着时才加宽（`_apply_widen` 会检查不越过画布右边距）。
不确认右侧为空就加宽会盖住别的元素，所以这条永远是显式声明，不自动推断。

## 替换文字的规矩

`_write_paragraphs` 只换字，保留第一段的一切格式：字号、字重、颜色、行距、
段落缩进。直接 `shape.text = ...` 会把设计师设的 run 属性一并丢掉——
在克隆页上，这是"模板的标题"和"一个默认段落待在标题该在的位置"的区别。

替换后仍要做溢出校验，但理由换了一条：

1. **设计者原本就放得下**。如果新文字在同一套度量下需要的空间不比原文多，
   那它就是放得下的，不管独立测算怎么说。这不是放松，是承认证据更强的一方。
2. 否则按 1pt 递减缩字，最低到原字号的 60%。克隆框无法变大，
   标题掉 2pt 仍然像模板，标题溢出圆角就不像了。到 60% 还不行就报错：
   那已经不是这套字阶了。

## 与既有质量规则的关系

模板模式下有三条要改：

- **背景**：画布颜色由模板决定，所以"不用刺眼背景"具体化为"不要交替"。
  绿封面 → 浅色正文 → 绿封底是首尾呼应，没问题；
  绿/白/绿/白反复才刺眼。纯白画布会被记一条 `notice-pure-white`，不算失败——
  门槛如果把合法的模板选择也判死，下一个人就会把门槛关掉。
- **字阶**：字阶是模板的，不是我们的。`template_ingest.py` 会把实测到的
  字号报出来，照着用。标题写进占位符时把字号**显式写上**：继承来的字号在文件里
  看不见，所有量字的工具都会以为这页没有标题。
- **页边**：模板自带的装饰常常贴边。`--min-margin 0.15` 告诉审计"贴边是有意的"，
  自己画的页面仍用默认 0.5。

其余规则一律不变：引用必须可追溯、正文放不下就报错、`[n]` 双向核对。

## 三条踩过的坑

1. **读不到颜色就等于没查。** 模板里的绿底是「主题色引用」或「渐变」，没有
   `rgb` 值；一个过宽的 `except` 会把它变成"没有背景"，于是背景检查一页都
   没测，还报 0 问题。必须解析主题色和渐变停点。
2. **页脚字号要够小。** 页脚 12pt 会被当成正文去比对，然后匹配到最近的说明文字框，
   报出一条指向错误形状的溢出。页脚用 10pt。
3. **文末单独一个数字不是文献。** 参考文献解析用 `\s+` 作分隔，会把页码、章节号
   后面的换行吞掉，把下一行当成它的正文。分隔符必须留在同一行（`[ \t]+`）。
